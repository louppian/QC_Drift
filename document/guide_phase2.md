# Annotation drift 연구를 위한 relabeling 가이드라인

# 1. 논문의 핵심 문장

서로 다른 ordinal annotation cohort에서 관측되는 차이를 코호트 분포 효과와 판독 기준 효과로 분해하고, 국소화된 criterion drift를 표적 재판독으로 검증·복구한다.

# 2. 논문의 구조

- 상위 개념: **Criterion drift in ordinal annotation**
- 핵심 방법: **Bidirectional decomposition**
- 임상적·실무적 결과: **Targeted re-annotation before cohort consolidation**

## Phase 2. Targeted re-annotation intervention

재레이블링은 후속 처리처럼 들어가 있었지만, 이제는 **가장 중요한 confirmatory experiment**가 되어야 한다.

정건 보고서([방향 반전 분해를 통한 코호트 편향과 판독 기준 드리프트 식별](https://inhamai.atlassian.net/wiki/spaces/CXRHAZ/pages/1481834501))는 2024 RB 상위 등급을 가장 유력한 재판독 대상으로 제안했다. 다만 방향 반전의 $\\delta$ 자체는 상대 차이만 보여주며 어느 연도가 이탈했는지를 결정하지 못하고, 2024를 지목하는 근거는 주로 영상 정합 L2에 의존한다는 한계도 스스로 명시했다.

drift의 존재와 위치는 비교적 강하게 찾았지만, 잘못된 방향은 아직 재판독으로 확인해야 한다.

따라서 **2024 RB grade 3·4만 재판독하면 안 된다.** 이는 가설을 확인하도록 설계된 실험으로 보일 수 있다.

다음 네 군을 포함해야 한다.

| 군 | 역할 |
| --- | --- |
| 2024 RB grade 3·4 | 주된 drift 후보 |
| 2024 RB grade 2·3 | 경계 특이성 확인 |
| 2026 RB grade 3·4 | 연도 대조군 |
| 2024 RT 또는 LB grade 3·4 | ROI 음성대조군 |

# 4. 재판독

## 4-1. 판독 방식

반드시 다음 조건을 갖춘다.

- 과거 label 비노출
- 모델 예측 비노출
- 촬영 연도 비노출
- 환자 식별자 비노출
- 이미지 순서 무작위화
- 10–15% hidden duplicate 삽입
    - 같은 이미지를 판독자가 모르게 한 번 더 넣는 것
    - 같은 이미지에 대해서 판독이 얼마나 흔들리는가를 측정(같은가 다른가)
    - **판독자가 원래 얼마나 흔들리는 사람인가를 측정**
    - 예를 들어, 동일 image에서 95% 판독기준이 유지되는데 재판독이 이전과 다르게 70%만 일치한다면 noise보다 다른 측면의 큰 변화(판단 기준)가 있었던 것으로 추측가능
- 판독 confidence 기록
- grade 3/4 경계 판단 근거를 간단한 구조화 문항으로 기록

이렇게 해야 재판독 결과가 기존 분석에 의해 anchoring되지 않는다.

## 4-2. 대상

| 구분 | 대상 | 선정 방식 | 판독 범위 | 목적 |
| --- | --- | --- | --- | --- |
| **핵심 보정군** | 2024년 기존 **RB grade 3 또는 4** 영상 | 해당 영상 전부 포함 | **RB 재판독** | 실제로 의심된 RB 3–4 레이블을 보정 |
| **내부 음성 대조군** | 2024년 RB의 **비의심 등급 구간** | RB grade 0–2에서 환자·등급별 층화표집 | **RB 재판독** | RB 전체가 불안정한 것이 아니라 3–4 구간에 문제가 집중되는지 확인 |
| **연도 비교군** | 2026년 기존 **RB grade 3 또는 4** 영상 | 여러 환자에서 층화표집 | **RB 재판독** | 3–4 경계 자체가 원래 어려운지, 2024년에만 불일치가 큰지 확인 |
| **ROI 특이성 검증군** | 위 집단 중 일부 환자의 대표 longitudinal sequence | 환자당 3–5장 정도의 mini-sequence 선정 | **RT, RB, LT, LB 모두 재판독** | 문제가 정말 RB에 집중되는지 확인 |
| **Hidden duplicate** | 전체 판독 세트의 일부 | 고유 sequence 또는 영상의 약 5% 중복 삽입 | 원래 판독 항목과 동일 | 현재 판독자의 intra-reader variability 확인 |

### Longitudinal sequence 구성 원칙

| 항목 | 원칙 |
| --- | --- |
| 환자 전체 영상 수 | 12–20장을 모두 보여주지 않음 |
| 기본 단위 | 환자별 **mini-sequence** |
| 핵심 보정군 | 기존 RB 3·4 영상은 모두 포함하고, 필요하면 앞뒤 문맥 영상 1장씩 추가 |
| 대조군 | 환자당 연속된 3–5장 정도 선정 |
| 제시 순서 | 환자 내부에서는 시간순 유지 |
| 환자 순서 | 전체 환자 순서는 무작위화 |
| 숨길 정보 | 촬영 연도, 기존 레이블, 대상군 종류, 예상 수정 방향 |
| 판독 기준 | 현재 사용 중인 동일한 기준으로 독립 재판독 |

## 가장 간단한 전체 구조

```
1. 2024 RB 3·4 전부 재판독
2. 2024 RB 0–2 일부 추가
3. 2026 RB 3·4 일부 추가
4. 위 환자 중 일부에서는 네 ROI 모두 재판독
5. 약 5% hidden duplicate 추가
6. 모든 환자를 한 번의 labeling round에서 무작위 순서로 판독
```

## 분석 질문

| 분석 | 확인할 내용 |
| --- | --- |
| 2024 RB 3·4 기존 vs 신규 | 실제 수정률과 수정 방향 |
| 2024 RB 3·4 vs 2024 RB 0–2 | 문제가 특정 등급 경계에 집중되는지 |
| 2024 RB 3·4 vs 2026 RB 3·4 | 2024 criterion drift인지, 경계 자체의 난이도인지 |
| RB vs RT·LT·LB | 문제가 RB에 공간적으로 특이적인지 |
| 본 판독 vs hidden duplicate | 관찰된 차이가 일반 판독 변동보다 큰지 |

### 환자별 영상 수를 제한하는 규칙 (labeling 부담을 줄이기 위해)

#### 1. 3·4 영상이 5장 이하인 환자

그 구간을 모두 포함.

```
직전 1장 + 모든 3·4 영상 + 직후 1장
```

대략 환자당 3–7장이 됨.

#### 2. 3·4 영상이 6장 이상인 환자

핵심 시점을 규칙적으로 축약.

- 3·4 구간의 첫 영상
- 중간 영상
- 마지막 영상
- 3→4 또는 4→3 전이가 있다면 전이 직전·직후
- 구간 바깥의 직전·직후 anchor 각 1장

중복을 제거하면 보통 **환자당 최대 6–7장**임.

예를 들어:

```
2 – 3 – 3 – 3 – 3 – 4 – 4 – 4 – 4 – 3 – 2
```

전체를 보이지 않고:

```
2 – 3(첫) – 3(전이 직전) – 4(전이 직후) – 4(마지막) – 3 – 2
```

정도로 구성.

## 4-3. 기록 방식

- **Grade (0–4)**

## 4-4. 재판독의 1차 평가변수

모델 성능 향상을 primary endpoint로 잡으면 안 된다. 먼저 **진단한 기준 이동이 실제로 복구되는지**를 평가해야 한다.

Primary:

1. 2024 RB 3/4 transition의 방향성
2. RB cutpoint displacement 감소
3. 방향 반전 δcorr\\delta\_{\\mathrm{corr}}δcorr의 감소 또는 0 포함
4. 2024–2026 RB의 threshold alignment
5. 표적군의 재판독 변화율이 대조군보다 높은지

Secondary:

- weighted κ
- MAE
- exact agreement
- within-one agreement
- 영상 특징과 grade 경계의 정합성
- 시계열 transition consistency

## 4-5. 성공 기준

재판독 후 단순히 “성능이 올랐다”가 아니라 다음 세 가지가 동시에 나타나야 한다.

> 표적군의 label이 체계적으로 이동하고,  
> 제안한 drift statistic이 정상화되며,  
> 독립 평가셋에서 모델의 calibration 또는 ordinal performance가 개선된다.

이 세 가지가 모두 나타나면 **탐지 → 원인 가설 → 개입 → 복구**가 완성된다.
